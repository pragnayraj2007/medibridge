# MediBridge — Work Log, 11 September 2026

MediBridge is an AI-assisted clinical intake and triage platform. A patient answers questions on a phone (or in a browser), a deterministic Safety Engine classifies urgency as RED / YELLOW / GREEN, and the doctor sees a prioritised case list with an AI-assisted summary. The AI never decides urgency; the doctor makes the final clinical decision.

**Live demo:** https://medibridge-xi.vercel.app

| Path | What opens |
|---|---|
| `/` | Home page with links to both apps |
| `/patient` | Patient app (web version of the Expo app) |
| `/doctor` | Doctor dashboard (live case list) |
| `/doctor/case/<id>` | One patient's case |
| `/api/*` | Backend API, proxied to https://medibridge-api-rose.vercel.app |

## 2. Architecture as built

```
Patient app (Expo: phone + web) ──┐
                                  ├──► /api  ──► Backend (FastAPI on Vercel) ──► Supabase (cases table)
Doctor dashboard (Next.js) ───────┘                    │
                                                       ├──► Groq openai/gpt-oss-120b (questions, extraction, summary)
                                                       └──► Safety Engine (pure Python, final urgency authority)
```

How one case flows:

1. The patient picks a language, enters age / sex / pregnancy, and gives consent.
2. The chat asks questions one at a time (`POST /intake/next-question`). After every answer the Safety Engine runs on the patient's words; if anything is RED, a red "tell staff now" banner appears immediately.
3. On submit (`POST /cases`), Groq extracts symptoms, duration, severity, history, medications, allergies and danger-sign flags, and writes a neutral summary for the doctor.
4. The Safety Engine combines the keyword flags and the Groq flags with age, pregnancy and any vital signs, and returns the level plus every rule that fired.
5. The case is saved in Supabase. The patient sees the level and guidance, and the case appears on the doctor dashboard within 5 seconds.
6. The doctor opens the case, reads the reasons, summary and full conversation, and marks it Reviewed or Follow-up.

Stack changes made today (with the user's approval):

- The patient app moved from Next.js to **React Native Expo**, as requested after the reference designs arrived.
- The backend is hosted on **Vercel** instead of Render, so everything is at one URL. Supabase can't run Python, so it stays the database only.

## 4. Backend (`apps/backend`)

**Tech:** Python, FastAPI, Pydantic, httpx, python-dotenv. Deployed on Vercel as a Python function.

### API

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Status plus storage mode (`supabase` / `memory`) and AI mode (`groq` / `rules`) |
| POST | `/intake/next-question` | Next chat question, plus a live Safety Engine check on the answers so far |
| POST | `/cases` | Submit intake → AI extraction → Safety Engine → save → return the case plus patient guidance |
| GET | `/cases?triage_level=&status=&limit=` | Case list for the dashboard, newest first |
| GET | `/cases/{id}` | One case (404 for unknown or invalid IDs) |
| PATCH | `/cases/{id}` | Set status: `new`, `reviewed` or `follow_up` |

Interactive API docs are at `/docs` when running locally.

Patient guidance text (not a diagnosis):

- **RED:** tell reception or nursing staff right now; if not at a hospital, go to the nearest emergency department or call 108 / 112.
- **YELLOW:** you will be seen as a priority; tell staff straight away if you feel worse.
- **GREEN:** your information has been sent; you will be seen in turn.

### Safety Engine (`safety_engine.py`)

- Pure Python with no network or AI: the same input always gives the same output. Engine version `iitt-adult-0.1`.
- Based on the WHO / ICRC / MSF **Interagency Integrated Triage Tool (IITT)**, adult version (age 12 and over).
- Input: a set of flags from a fixed vocabulary, plus age, pregnancy and optional vitals (HR, RR, SpO2, temperature, BP).
- Output: the level plus every rule that fired, most urgent first. Each rule is labelled `IITT` or `MediBridge` (our extra-cautious rules).
- Unknown flags are ignored, so the AI cannot invent new rules.

**RED rules:**

- Single danger signs: unresponsive, stridor, respiratory distress, blue lips (central cyanosis), capillary refill over 3 seconds, weak fast pulse, heavy bleeding, high-risk trauma, poisoning, threatened limb, snake bite, violent or aggressive, active convulsions, low blood sugar.
- Heart rate below 50 or above 150.
- Acute chest or abdominal pain over age 50. If age is unknown it is treated as over 50 (MediBridge rule).
- Pregnant with any of: heavy bleeding, severe abdominal pain, seizures, altered mental status, severe headache, visual changes, active labour, trauma, or BP of 160/110 or higher.
- Any two of: altered mental status, stiff neck, fever or low temperature, headache.

**YELLOW rules:**

- IITT yellow signs: mouth, throat or neck swelling; wheezing; vomiting everything or ongoing diarrhoea; unable to eat or drink; severe pallor; ongoing bleeding; recent fainting; confusion or agitation; sudden weakness; stroke-like symptoms; sudden vision problems; severe pain; spreading rash; limb deformity or open fracture; dislocation; other trauma or burns; sexual assault; testicular pain; unable to pass urine; dog or animal bite / needlestick (needs rabies or other prophylaxis); pregnancy complications.
- Vitals: HR below 60 or above 130, RR below 10 or above 30, temperature below 36 or above 39 °C, SpO2 below 92%.
- MediBridge rules: chest or abdominal pain at age 50 or under, reported breathing difficulty, recent seizure, severe headache, and every child under 12 (the adult tool isn't validated for children, so they are never auto-GREEN).

**GREEN:** none of the above.

### Keyword safety net (`keywords.py`)

- English regular expressions that turn the patient's own words into flags, for example "can't breathe" → respiratory distress, "hit by a bus" → high-risk trauma, "32 weeks pregnant" → pregnancy.
- Always runs, with or without AI. The AI can add flags but never remove them, so a failed or wrong AI call can't hide a danger sign.
- Deliberately cautious: no negation handling ("no chest pain" still flags chest pain), because over-triage is the safe way to fail.
- Guarded against known false alarms: "flu shot", "heartburn", "fall asleep", "food poisoning", "can't see a doctor".

### AI (`ai.py`)

- Groq model `openai/gpt-oss-120b`, called over the REST API (no SDK).
- **Next question:** a friendly intake assistant that asks one question at a time in the chosen language, never diagnoses, never states urgency, never gives treatment advice, and replies DONE after about 5–7 questions.
- **Extraction:** JSON with symptoms, duration, severity, history, medications, allergies, danger-sign flags (only from the Safety Engine vocabulary), and a 3–5 sentence neutral summary. The summary is told never to state or imply urgency, because the Safety Engine decides that.
- **Fallback:** with no key, or if Groq fails, the chat uses 6 scripted questions and the summary is built from the patient's words. The app keeps working.

### Storage (`storage.py`) and database

- Uses Supabase over its REST API when `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` are set; otherwise keeps cases in memory (local development only).
- Supports Supabase's new `sb_secret_…` keys: the key goes only in the `apikey` header, as Supabase requires. Old JWT keys are also supported.
- `supabase/schema.sql` creates the `cases` table: id, timestamps, status, triage_level, language, and patient, messages, documents, vitals, extraction, summary and triage (stored as JSON). It has indexes, Row Level Security switched on, and access only for the backend's service role (the public roles get nothing).

### Other backend files

- `models.py` — input validation: age 0–130, message length, and at most 100 messages / 20 documents.
- `vercel.json` — FastAPI framework, 60-second function limit.
- `requirements.txt` — fastapi, uvicorn, python-dotenv, httpx, pydantic (unused packages removed; version ranges loosened so it installs on new Python versions).
- `tests/test_safety_engine.py` — 16 tests covering green/red/yellow rules, age rules, pregnancy, the "two of" rule, vitals, children, unknown flags, reason ordering, determinism, keyword phrases, the demo case, and false-alarm guards. All pass in the cloud and on the PC.

## 5. Doctor dashboard (`apps/doctor-dashboard`)

**Tech:** Next.js 14.2.35 (App Router), React 18, Tailwind CSS. Also hosts the home page and the patient web app.

- **Home `/`** — MediBridge title, Patient App and Doctor Dashboard cards, the RED / YELLOW / GREEN key, and a note that urgency comes from the rule-based Safety Engine, not the AI.
- **Dashboard `/doctor`**
  - Refreshes every 5 seconds, with a Live / Offline indicator.
  - Count cards for open RED / YELLOW / GREEN cases; click one to filter.
  - Search by name or complaint, plus a triage filter.
  - Sorted open cases first, then most urgent, then newest; reviewed cases are greyed out.
  - Columns: patient (name, age, sex, pregnant), complaint, triage badge, time ago, status, View link.
- **Case page `/doctor/case/<id>`**
  - Triage colour bar with the submission time.
  - Patient card: phone, pregnancy, language.
  - **Safety Engine panel** with every rule that fired and its source.
  - **Mark as Reviewed** and **Request Follow-up** buttons that save to the database.
  - AI Clinical Summary, labelled with the model, or "AI unavailable — rule-based".
  - Extracted details: symptoms, duration, severity, history, medications, allergies, detected flags.
  - Documents and vitals when present, and the full intake conversation.
- **API proxy** — `next.config.js` forwards `/api/*` to `BACKEND_URL`, so the browser never calls another site (no CORS problems). `/patient/*` serves the patient web app.

### Problems hit and fixed during deployment

- **Wrong folder:** the PC's `patient-app` folder was still the old Next.js app, so Expo couldn't find react-native. Created a clean `patient-mobile` folder and installed with `npx expo install` so versions match SDK 57; pinned `react-native-worklets` to the SDK version.
- **Dashboard "Offline":** the browser couldn't reach the backend directly. Fixed by proxying `/api` through Next.js.
- **Blocked tools:** the Windows update broke the remote shell, so helper scripts were double-clicked from File Explorer instead. The cloud could not reach Vercel, Supabase or npm directly, so all builds and deploys ran from the PC.
- **Render leftovers:** `vercel link` turned the old `render.yaml` into a "services" config. Removed it, wrote a plain FastAPI `vercel.json`, and switched the project framework to FastAPI through the Vercel API.
- **Missing icons:** Vercel never uploads folders named `node_modules`, so the patient app's icon font was missing on the web. The export script now moves those files to `assets/nm` and updates the references.
- **Route clash:** the old dashboard route at `/patient/[id]` clashed with the patient web app, so the case page moved to `/doctor/case/[id]` and the old route is excluded from uploads.
- **Supabase keys:** new-style `sb_secret_` keys can't be sent as a Bearer token, so storage now sends them only in the `apikey` header.
- **Groq key not saved at first:** the Vercel CLI asked an interactive question; added `--sensitive` to skip it.

## 8. Known limitations and next steps

**Limitations**

- **No login on the dashboard:** anyone with the link can see cases. Use demo data only; don't enter real patient information.
- **Login and OTP are UI only**, and consent isn't stored with the case.
- **Vital-sign thresholds need clinical review.** They come from two versions of the IITT that don't fully agree. RED/YELLOW/GREEN is an urgency class, not a diagnosis.
- **The keyword safety net understands English only.** Hindi or Telugu answers rely on the AI flags.
- **Upload and mic are UI only:** the upload screen doesn't read documents and the mic button does nothing yet.
- **Next.js 14 no longer gets security updates.** Plan an upgrade to Next.js 15.5.24 or later.
- **Keys:** the Supabase secret key and Groq key were shared in chat. The user decided not to change them.

**Suggested next steps**

1. Voice: Sarvam Saaras v4 for speech-to-text and Bulbul v3 for text-to-speech on the chat screen.
2. Documents: real file upload, then PaddleOCR / Gemini to extract text into the case.
3. Keyword safety net for Hindi and Telugu.
4. Simple doctor login for the dashboard.
5. Merge `feature/demo-readiness`, then connect Vercel to Git for automatic deploys.
6. Clinician review of the Safety Engine thresholds.
